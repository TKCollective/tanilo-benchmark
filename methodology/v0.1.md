# Methodology v0.1 — AgentOracle Benchmark

**Status:** Active. Submissions open.
**Effective:** 2026-06-01
**Reference harness:** [TKCollective/agentoracle-eval-harness](https://github.com/TKCollective/agentoracle-eval-harness)

This document is the normative methodology for v0.1 of the AgentOracle Benchmark. Submissions are valid only against the methodology version they were made under; future versions ship as separate documents and submission tracks.

## Test set

| Property | Value |
|---|---|
| Source | AVeriTeC dev split (Schlichtkrull et al., 2024) |
| Total claims | 500 |
| Held-out subset | 100 (deterministic split, indices in `methodology/v0.1-heldout-indices.json`) |
| License | Source dataset license terms apply |
| Update cadence | Frozen for v0.1; v0.2 may incorporate additional or replacement sets |

## Verdict mapping

A submission's verifier produces a raw verdict per claim. The benchmark scoring maps that verdict to one of the four AVeriTeC ground-truth labels per the table below. Any adversarial-vulnerable signal on a `supported` verdict promotes the prediction to `Conflicting Evidence/Cherrypicking`.

| Verifier `verdict_raw` | Adversarial result | Predicted AVeriTeC label |
|---|---|---|
| `supported` | `resilient` or `not_checked` | `Supported` |
| `supported` | `vulnerable` | `Conflicting Evidence/Cherrypicking` |
| `refuted` | (any) | `Refuted` |
| `unverifiable` / `unknown` / `not_enough_evidence` | (any) | `Not Enough Evidence` |

## Scoring

Two scores are reported per submission:

1. **Full-set accuracy** — proportion of all 500 claims where the predicted label matches the AVeriTeC ground-truth label.
2. **Held-out accuracy** — proportion on the 100-claim held-out subset.

Per-label accuracy and confusion data are reported as supplementary information. Overall ranking is by held-out accuracy.

Errors (timeout, no sources, runtime failure) count as `Not Enough Evidence` predictions for scoring purposes.

## Calibration discipline

Every submission MUST declare:

| Field | Description |
|---|---|
| `anchor_dataset` | Name of the dataset the verifier's confidence is calibrated against |
| `anchor_seed` | Stable identifier of the calibration run |
| `valid_until` | ISO date by which calibration is expected to remain valid |

Submissions whose `valid_until` has passed are tagged `stale` in the registry but remain present for historical comparison.

## Submission format

Each submission produces:

1. `submissions/<operator-id>/v0.1.json` — the submission metadata, scores, calibration declaration
2. `submissions/<operator-id>/v0.1-results.jsonl` — the raw per-claim results
3. (optional) `submissions/<operator-id>/v0.1-receipts.jsonl` — JWS-signed receipts for each per-claim verification

Submissions including signed receipts can be independently verified using [`@agentoracle/receipt-verify`](https://github.com/TKCollective/agentoracle-receipt-verify) or any compatible verifier.

## Conformance review

Submission PRs are reviewed against:

- Format conformance (schema, required fields, file structure)
- Methodology conformance (correct test set, deterministic held-out split, valid verdict mapping)
- Reproducibility (raw results.jsonl present and consistent with claimed scores)

Submission accuracy is NOT reviewed. Operators are responsible for their own scores.

## Versioning

- v0.1 — Active. Single-modality (text claims), AVeriTeC-based.
- v0.2 — Drafting. Multi-modal (image, audio, code) extension. Open RFC.
- Future versions ship as separate methodology documents. Submissions remain valid against the version they were made under indefinitely.
